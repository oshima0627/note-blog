# Claude Code v2.1.219の更新：サブエージェントの入れ子が深さ3に

*2026年7月27日時点の情報です。料金・仕様は変わりやすいため、最新は公式ドキュメントでご確認ください。*

この記事でわかること：

- サブエージェントの「入れ子（ネスト）」が既定で深さ3まで許可されたこと
- 動的ワークフローに「15エージェント未満」というサイズの目安が既定で入ったこと
- サンドボックス実行を狭める新設定と、ヘッドレス実行まわりの改善

Claude Code は7月24日にv2.1.219、7月25日にv2.1.220をリリースしました。v2.1.219では既定のOpusモデルがClaude Opus 5に切り替わりましたが、この点は別記事で扱ったため、本記事ではそれ以外の変更、とくにマルチエージェント（複数のAIエージェントで作業を分担する仕組み）まわりの更新を中心にまとめます。

## サブエージェントの入れ子が既定で深さ3に

これまでサブエージェント（メインのエージェントが起動する補助エージェント）は、既定では自分がさらに別のサブエージェントを起動できませんでした。入れ子の深さは1に制限されていました。

v2.1.219では、サブエージェントがさらにサブエージェントを起動できる深さが、既定で最大3まで引き上げられました。公式の変更履歴には「Subagents can now spawn nested subagents up to depth 3 by default (was 1)」と記載されています。入れ子を使いたくない場合は、環境変数 `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH=1` を設定すると従来どおり無効化できます。

**読者への影響**：調査や実装を階層的に分担させる、いわゆる多階層のエージェント構成が既定で組みやすくなります。一方で、意図せず多くのエージェントが動くとトークン消費が増えるため、規模の管理が重要になります。この点は次の「サイズの目安」とセットで理解すると分かりやすいです。

なお、直前のバージョン（v2.1.217/218）では、サブエージェントを「同時」に動かす数に上限が入りました。今回の変更は「同時実行数」ではなく「入れ子の深さ」に関するものです。軸が違う設定なので、混同しないようにしておくと安心です。

## 動的ワークフローに「15エージェント未満」の目安が既定で

v2.1.219では、動的ワークフロー（複数エージェントを組み合わせて自動で仕事を進める仕組み）に、既定で「mediumサイズ＝15エージェント未満を目安にする」というガイドラインが入りました。

これはあくまで助言的な目安（advisory）で、強制上限ではありません。別のサイズや「制限なし」を選びたい場合は、`/config` の「Dynamic workflow size」から変更できます。また、この目安を設定ファイル側から指定できる `workflowSizeGuideline` というキーも追加されました。実行中は、現在の既定サイズがワークフローのステータス表示に出るようになっています。

**読者への影響**：エージェントを増やしすぎてトークンを浪費する事故が起きにくくなります。前述の入れ子深さの拡張とあわせて、「規模は既定で控えめ、必要なら明示的に広げる」という方針に整理された形です。

## サンドボックスを狭める新設定とヘッドレス実行の改善

セキュリティと自動実行まわりでも変更があります。

- **`sandbox.network.strictAllowlist`**：サンドボックス（隔離環境）で動くコマンドについて、許可リストにないホストへの通信を、確認を挟まずに拒否する設定が追加されました。外部通信を厳しく絞りたい環境で有効です。
- **`DirectoryAdded` フック**：セッションの途中で `/add-dir`（作業ディレクトリの追加）やSDKの登録リクエストで新しい作業ディレクトリが登録された後に発火するフックが追加されました。
- **ヘッドレス実行の可視化**：`--mcp-config` の検証で読み飛ばされた設定が、ヘッドレスのstream-json初期化イベントに `mcp_server_errors` として出るようになりました。ターミナル実行では起動時に警告が出ます。
- **`claude -p` の出力保持**：ターンの途中でAPIエラーが起きたとき、それまでに生成済みの回答が消えてしまう不具合が修正されました。

**読者への影響**：CI（継続的インテグレーション）や自動化パイプラインでClaude Codeを回している人にとって、失敗時の原因が見えやすくなり、途中結果が失われにくくなります。MCP（外部ツール連携の仕組み）の設定ミスも起動時に気づけます。

## その他の修正（v2.1.220まで）

v2.1.220（7月25日）は「バグ修正と信頼性の改善」が中心のリリースとされています。v2.1.219には他にも、`/model` 選択画面の表示改善、Remote Control（遠隔操作）まわりの状態不整合の修正、Windowsの `CLAUDE_CODE_GIT_BASH_PATH` の扱い修正、スクリーンリーダー対応の改善などが含まれています。詳細は公式の変更履歴をご確認ください。

## 筆者の見方

今回の一連の変更は、「マルチエージェントをより深く組めるようにしつつ、規模は既定で抑える」という方向でバランスを取った印象です。入れ子の深さが3に増えたことで表現力は上がりますが、トークン消費は増えやすくなります。まずは小さく試し、`/config` のサイズ目安や環境変数で自分の使い方に合わせて調整するのがおすすめです（これは筆者の見方です）。
