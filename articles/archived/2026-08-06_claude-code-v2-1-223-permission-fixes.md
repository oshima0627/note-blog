# Claude Code v2.1.223：権限まわりの抜け穴4件を修正

※本記事は **2026年8月6日時点**の情報です。仕様・料金は変わりやすいため、最新は公式ドキュメントでご確認ください。

## この記事でわかること

- Claude Code v2.1.223 で修正された、権限チェックとサンドボックスの抜け穴4件の中身
- 自分の環境が更新されているかの確認方法（インストール方法によって自動更新の有無が違います）
- 気づきにくい挙動変更（`/review` の意味が変わった、1Mコンテキスト抑止の対象が広がった）

---

## 1. 何が起きたか

2026年8月6日、Claude Code の **v2.1.223** が公開されました。公式 changelog に並ぶ変更のうち、目立つのは**権限チェックとサンドボックスの境界に関する修正が4件**含まれている点です。

Claude Code は、Bash コマンドの実行やファイル編集を「許可・拒否」のルールで制御しています。今回修正されたのは、その**制御をすり抜けられてしまう経路**です。

なお、本稿執筆時点で anthropics/claude-code の GitHub Security Advisories 一覧を確認したところ、2026年8月公開の項目は掲載されていませんでした（最新の掲載は2026年6月付）。したがって本記事は、CVE番号などではなく**公式 changelog の記述**を根拠にしています。

## 2. 修正された4件の中身

公式 changelog の記述にもとづく整理です。

### Bash コマンドが自分の一部を隠せた問題

細工したコマンドが、**自身の一部を権限チェックから隠せてしまう**不具合が修正されました。つまり、チェック側が見ているコマンド文字列と、実際に実行される内容がズレる可能性があったということです。

### 承認ダイアログでコマンドの一部が見えなかった問題

タブ文字や**不可視の Unicode 文字**で埋められたコマンドが、承認ダイアログ上でコマンドの一部を隠せてしまう問題が修正されました。

**読者への影響:** これが1と2で分かれている点が重要です。1は「チェックロジックを欺く」経路、2は「人間の目を欺く」経路です。承認ダイアログに表示された文字列を読んで Yes を押していても、実際に走る内容が違いうる、という話になります。信頼していないリポジトリやスキル、MCP サーバーを触る人ほど影響が大きい修正です。

### ワークフロースクリプトがサンドボックスの外でコードを実行できた問題

ワークフロースクリプトが動的 `import()` を使い、**ワークフローのサンドボックス外でコードを実行できた**不具合が修正されました。

### bypassPermissions が組織ポリシーを無視できた問題

エージェント定義の `bypassPermissions` モードが、**組織側の「bypass-permissions を無効化する」ポリシーを無視していた**権限ギャップが修正されました。組織で権限バイパスを禁止していても、エージェント定義側から迂回できた形になります。

**筆者の見方:** 4件のうち3件は「制限をかけたつもりが、かかっていなかった」類のものです。Claude Code を自動実行（バックグラウンド、ルーチン、CI）で回している人ほど、更新の優先度は高いと考えられます。

## 3. まずやること：バージョン確認と更新

自動更新されるかどうかは、**インストール方法によって違います**。ここは公式ドキュメントに明記されています。

- **ネイティブインストール（install.sh / install.ps1）**: バックグラウンドで自動更新される
- **npm グローバルインストール**: `npm install -g @anthropic-ai/claude-code@latest` で更新
- **Homebrew**: 自動更新されない。`brew upgrade claude-code`（または `claude-code@latest`）
- **WinGet**: 自動更新されない。`winget upgrade Anthropic.ClaudeCode`
- **apt / dnf / apk**: 自動更新されない。各パッケージマネージャの upgrade コマンドで更新

現在のバージョンは次のコマンドで確認できます。

```bash
claude --version
```

即時に更新したい場合は次を実行します。

```bash
claude update
```

なお、Homebrew の `claude-code` cask は **stable チャンネル**を追う設定で、公式ドキュメントによれば「概ね1週間ほど遅れる」とされています。最新の修正をすぐ入れたい場合は、自分がどのチャンネルにいるかも合わせて確認してください。

更新後は、起動中のセッションを一度再起動しておくのが無難です。更新は「次回起動時」に反映されます。

## 4. 気づきにくい挙動変更

セキュリティ以外にも、黙って動きが変わる変更が入っています。

### `/review` が `/code-review` の別名になった

`/review` は `/code-review` のエイリアスになりました。現在の差分または PR をレビューします（`/code-review <level> <pr#>`）。深いクラウドレビューを行う場合は `/code-review ultra` です。

また、effort レベルを指定せずに `/code-review` を実行すると、**前回自分が打ったレベルを再利用する**ようになりました。変えたいときは `/code-review high` のようにレベルを明示します。

### 1Mコンテキスト抑止の対象が広がった

`CLAUDE_CODE_DISABLE_1M_CONTEXT` の挙動が変わりました。従来の「固定リストのモデルのみ」ではなく、**ネイティブに1Mウィンドウを持つ Claude モデルすべて**を、自動コンパクションによって200Kに抑えるようになっています。自動コンパクションが200Kに抑えられていない場合は、起動時に警告が出ます。

あわせて、認識されないモデルIDのセッションも、想定コンテキストウィンドウ内に収まるよう自動コンパクトされるようになりました。従来の挙動に戻すには `CLAUDE_CODE_DISABLE_UNKNOWN_MODEL_WINDOW_ENFORCEMENT=1` を設定します。

**読者への影響:** ゲートウェイ経由や独自 `ANTHROPIC_BASE_URL` でモデルを使っている場合、これまでより早くコンパクションが走る可能性があります。長いセッションの挙動が変わったと感じたら、この変更を疑ってください。

### その他

- マーケットプレイスの管理設定 `strictKnownMarketplaces` / `blockedMarketplaces` に、**オーナー単位のワイルドカード**（`"owner/*"`）が使えるようになりました。GitHub の組織配下をまとめて許可・ブロックできます
- ワークフローエージェントやフォークしたスキル、スラッシュコマンド、再開したバックグラウンドエージェントで、**要求したサブエージェントのモデルが制限されて親モデルが代わりに動く場合に警告**が出るようになりました
- クラウドセッションに `/teleport` のヒントが表示され、`claude --teleport <session id>` でローカルに引き継ぐ方法が案内されるようになりました

## 5. まとめ

今回のリリースは、新機能よりも**「かけたはずの制限が効いていなかった」箇所の修正**が主軸です。特に、承認ダイアログの表示を信じて Yes を押す運用をしている場合、2件目の不可視 Unicode の修正は直接効いてきます。

Homebrew・WinGet・Linux パッケージマネージャ経由の方は自動更新されないため、**手動での更新が必要**です。まずは `claude --version` で自分のバージョンを確認するところから始めてください。
