# Claude Codeのセッション記録が正式版に：誰が何を見られるのか

2026年8月26日時点の情報です。料金・仕様は変わりやすいため、最新は公式ドキュメントでご確認ください。

この記事でわかること

- Claude Code のセッション記録（トランスクリプト）を組織が取得できる仕組みが、正式版になりました
- 対象は Claude Enterprise 組織のみで、個人の Pro / Max プランは対象外です
- 記録に含まれるもの・含まれないものと、記録されないケース

## 何が発表されたのか

2026年8月26日、Claude Platform のリリースノートに、Compliance API のセッション取得エンドポイントが Cowork と Claude Code のセッションについてベータを卒業した、と記載されました。

Compliance API は、組織の管理者・法務・セキュリティ担当が、自社の Claude 利用状況をプログラムから取得するための API です。これまで段階的にベータで提供されてきました。公式リリースノートの日付を並べると、次のような経緯です。

- 2026年8月3日: claude.ai の web / モバイルで動く Cowork セッション（リモートセッション）の取得がベータで追加
- 2026年8月11日: 利用者のマシン上で動く Cowork / Claude Code セッション（ローカルセッション）の取得がベータで追加
- 2026年8月26日: Cowork と Claude Code のセッションについて、ベータを卒業（安定版に）

同じ8月26日には、Claude Science と Microsoft 365 向け Claude アドイン（Excel / PowerPoint / Word / Outlook）のセッション取得も追加されましたが、こちらはベータのままです。

## 対象は Claude Enterprise 組織だけです

まず範囲を確認しておきます。公式ドキュメントには「このページのエンドポイントは Claude Enterprise 組織のみが利用できます」と明記されています。個人で Pro / Max プランを契約して Claude Code を使っている場合、この仕組みで誰かがあなたのセッションを取得することはありません。

有効化は組織の primary owner が claude.ai の Organization settings > API で行い、親組織から配下の組織へ引き継がれます。取得には claude.ai で作る Compliance Access Key と `read:compliance_user_data` スコープが必要で、新しいキーや設定、クライアントの更新は要らないとされています。つまり、勤務先が Claude Enterprise で Compliance API を有効にしていれば、Claude Code 側で何かを設定しなくても記録の対象になります。

なお、記録は有効化した時点から始まります。ドキュメントには、一覧に「組織で取得が始まる前に実行されたセッション」が含まれることがあり、その場合は本文が取得不可として返る、と書かれています。

## 取得されるのは「APIに届いたやり取り」だけです

誤解しやすい点なので、公式の説明をそのまま紹介します。ローカルセッションについて、Anthropic は「各会話は、リクエストが Claude API に届いた時点でサーバー側に記録される。デバイスには何もインストールされず、クライアントがすでに Claude API に送っているリクエスト以上のものは収集されない」と説明しています。

したがってトランスクリプトが示すのは、Claude に何を依頼し、Claude が何を返したかであって、デバイス上で起きたことそのものではありません。ファイルやネットワークの動きは、トランスクリプト内のツール呼び出しと結果を通してしか見えず、API に一度も届かなかったもの（セッションが送らなかったローカルファイルなど）は記録されません。

端末の種類やワークスペースのパスといったホスト・デバイスのメタデータは含まれず、トークン使用量とコストも含まれません（後者は Claude Enterprise Analytics API 側で扱われます）。

## 含まれるもの・含まれないもの

公式ドキュメントの記載を箇条書きにすると、次のとおりです。

含まれるもの

- ユーザーのプロンプト
- アシスタントのテキスト出力
- ツール呼び出しと、ツール結果のテキスト部分
- ツール経由で Claude が読んだファイルの中身（テキストのみ）とファイル名
- `CLAUDE.md` などのプロジェクト指示ファイル。通常のユーザー発話として現れます
- スキルの内容。クライアントがメッセージ本文として送った場合に現れ、他のユーザーテキストと区別されません

含まれないもの

- 思考（thinking）ブロック
- リクエストのシステムプロンプト。`[system prompt content not shown]` という目印のメッセージに置き換わります
- ツール定義と MCP サーバーの設定
- 画像・PDF などのバイナリや構造化ブロック。`[image content not shown]` のようなプレースホルダーになります
- 引用（citation）のメタデータ

サイズの上限もあります。ツール入力と、ツール結果の各テキストは既定で 10,000 バイトに切り詰められ、リクエスト時の指定で 1 MiB 程度まで引き上げられます。

そして重要な注意書きが1文あります。トランスクリプトの内容について「URL・認証情報・個人データにマスクは一切かからないため、トランスクリプトは機微なデータとして扱うこと」と明記されています。これは取得する側への注意ですが、使う側にとっても意味が同じです。会社のアカウントで Claude Code に貼り付けた API キーやトークンは、そのままの形で記録に残りうる、ということです。

## 記録されないケース

公式ドキュメントは、次のケースを「セッションエンドポイントが返さないもの」として挙げています。

- Claude Console の API キーで認証している Claude Code のセッション
- Amazon Bedrock、Google Cloud、Microsoft Foundry など第三者クラウド経由で実行している Claude Code のセッション
- Claude Code on the web。クラウドで動きますが、リモートセッションの対象は Cowork のみです
- HIPAA readiness を有効にしている組織のローカルセッション（ローカルセッションのデータ自体が取得されません）
- ゼロデータ保持（ZDR）が適用されるセッション

## 保存期間は既定で6年

ローカルセッションの内容は、取得時から既定で6年間保存されます。組織が有限の会話保持期間を設定している場合はそちらが優先され、複数設定されている場合は最も短いものが適用されます。リモートセッションは6年です。

期間の変更は2通りの効き方をします。設定を変えた時点で、現在の期間より古い活動は返らなくなります。一方、各メッセージは取得された当時の期間で保存されるため、あとから期間を延ばしても、すでに期限切れになった内容は戻りません。

セッションエンドポイントは読み取り専用で、ローカル・リモートともに Compliance API からセッションを削除することはできません。

## 筆者の見方：個人開発者への実務的な影響

ここからは筆者の見方です。この変更自体が「新しく監視が始まった」ものではありません。ベータでできていたことが安定版になった、というのが正確な理解です。

そのうえで、業務で Claude Code を使っている人にとっては、次の2点が実務的な確認事項になると考えられます。

1つは、認証方式によって扱いが変わることです。会社の Claude Enterprise アカウントでサインインして使う場合と、Console の API キーや Bedrock 経由で使う場合とで、記録の対象かどうかが変わります。自分がどちらで動かしているかは、把握しておいて損はありません。

もう1つは、貼り付ける内容です。マスクがかからないと公式が明記している以上、認証情報や個人データを会話に直接貼るのは、記録の有無にかかわらず避けたほうが無難です。ローカルファイルでも、Claude が読み込んで API に送った時点で内容はトランスクリプトに載ります。

Anthropic は、Cowork と Claude Code のセッション内容の取得手段として、OpenTelemetry によるログ収集ではなく Compliance API を推奨しています。組織側で監査基盤を検討している場合は、この推奨が判断材料になります。

## あわせて：Admin API が CLI と各言語 SDK から使えるように

同じ8月26日のリリースノートには、Admin API が `ant` CLI と Python / TypeScript / C# / Go / Java / PHP / Ruby の各 SDK で `client.beta.organization` として使えるようになった、という項目もあります。組織情報、メンバー、招待、ワークスペース、APIキー、レート制限、サービスアカウントなどが対象です。使用量・コストのレポートと、Claude Enterprise のユーザー管理・分析エンドポイントは引き続き curl のみとされています。
