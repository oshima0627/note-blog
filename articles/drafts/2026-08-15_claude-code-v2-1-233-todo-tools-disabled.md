# Claude Code更新：新モデルでToDoリストが出なくなりました

※2026年8月15日時点の情報です。仕様は変わりやすいため、最新は公式ドキュメントでご確認ください。

## この記事でわかること

- Claude Code v2.1.233で、タスク管理ツール（TaskCreate等・TodoWrite）が新しいモデルでは既定で提供されなくなったこと
- 対象モデルと、従来どおり使える例外、そして元に戻す方法
- 同じリリースに含まれるWindowsの資格情報漏えい経路の修正など、確認しておきたい変更

## 作業中のタスクリストが表示されなくなりました

2026年8月14日公開のClaude Code v2.1.233で、タスク管理まわりのツールの扱いが変わりました。公式の「Tools reference」には、次のように書かれています。

v2.1.233以降、`TodoWrite`・`TaskCreate`・`TaskGet`・`TaskUpdate`・`TaskList` の5つは、**Opus 4.8 / Sonnet 5 / Fable 5 / Mythos 5、およびそれらの後継モデルでは、明示的に有効化しない限り提供されない**とされています。

理由も公式ドキュメントに明記されています。これらのモデルは書き出したチェックリストがなくても複数手順の作業を追えること、そしてツールの定義とリマインダーがコンテキストを消費すること、の2点です。

**読者への影響**: 対象モデルを使っていると、作業中に画面のタスクリストへ項目が追加されなくなります。Claudeが手を抜くようになったわけではなく、進捗表示の手段が変わったという整理です。長い作業の進み具合を目視で追っていた人は、体感が変わる部分だと思います（筆者の見方）。

## 従来どおり使えるケース

すべての環境で消えるわけではありません。公式ドキュメントによると、次のケースでは引き続きツールが提供されます。

- Opus 4.7 など、上記リストに含まれないモデルを使っている場合（4つのTaskツールが既定で提供されます）
- バックグラウンドセッション（agent view）で動かしている場合
- Claude Code on the web で動かしている場合

なお `TodoWrite` 自体は、v2.1.233より前からTaskツール群に置き換えられており、`CLAUDE_CODE_ENABLE_TASKS=0` を設定したときだけ使える扱いになっています。今回はその手前で、Taskツール群ごと対象モデルから外れた形です。

## 元に戻す方法は4つ

対象モデルでも使いたい場合、公式ドキュメントは次の方法を挙げています。

- 環境変数 `CLAUDE_CODE_ENABLE_TODO_TOOLS=1` を起動前に設定する（例: `CLAUDE_CODE_ENABLE_TODO_TOOLS=1 claude`）。これで全モデル・全プロバイダーで提供されます
- `--allowedTools` でツール名を指定する（例: `claude --allowedTools TaskCreate`）
- `--tools` に列挙する。ただしこのフラグはセッションの組み込みツールを列挙したものだけに絞るため、他に使う組み込みツールも一緒に書く必要があります
- Agent SDKでは `allowedTools` / `tools` オプションが上記2つのフラグと同じ働きをします

## サブエージェント・エージェントチームへの波及

見落としやすいのがサブエージェント側です。公式ドキュメントによると、サブエージェントがこれらのツールを持てるのは**自分のセッションが持っているときだけ**で、サブエージェントが別モデルで動いていても同じです。

エージェントチームの場合、同一プロセス内のチームメイトはセッションに追従します。一方、別ペインで動くチームメイトは独立したClaude Codeプロセスのため、そのモデル自身の条件で決まります。Taskツールがない場合、エージェント同士は共有タスクリストではなくメッセージで連携します。

## Agent SDKを使っている場合の対象バージョン

Agent SDK側にも同じ変更が入っています。公式ドキュメントの記載は、TypeScript版 0.3.233以降、Python版 0.2.139以降です。

**読者への影響**: SDKでメッセージストリームを監視し、`TodoWrite` や `TaskCreate` の `tool_use` ブロックから進捗を描画していた場合、対象モデルではそのブロックが流れてきません。進捗表示が空になる形で壊れるため、監視コードを持っている人は先に確認しておくのが安全です。

## 同じリリースの安全性・安定性の修正

v2.1.233には、権限・安定性まわりの修正も含まれています。公式changelogから、影響が分かりやすいものを挙げます。

- Windowsで、NTの `\??\` デバイスプレフィックス付きパスがUNCパス検証を回避できた問題を修正。NTLM資格情報の漏えい経路をふさぐものと説明されています
- Linuxで、サンドボックス有効時にアイドル状態のセッションがCPUコアを1つ100%使い続けることがあった問題を修正
- Claude DesktopやVS Code配下で、権限プロンプト時にNotificationフックが発火しなかった問題を修正
- ユーザーやプロジェクトのスキルが同名の内蔵スキルを隠していると、`/checkup` `/review` などのエイリアスが `-p` モードで「Unknown command」になっていた問題を修正

またWindowsでは、前日のv2.1.232で入ったBash権限まわりの変更が一部巻き戻されています。`cd <dir> && <command> > file` のような通常のコマンドでautoモードが繰り返し手動承認を求める回帰が発生したためで、Cygwin形式のシンボリックリンクと入力リダイレクト（`< file`）についての変更は、範囲を狭めた形で後のリリースに戻る予定とされています。

## GitLabまわりの対応が広がりました

v2.1.232とv2.1.233では、GitLab関連の対応が続けて入りました。

- `--worktree` フラグと `claude agents` ビューがGitLabのマージリクエストURLに対応（MRは `!N` 表記で表示）
- GitLabトークン各種（`glrt-` `gloas-` `glptt-` など）のシークレット伏せ字化と、`glpat-` / `gldt-` トークンの完全な伏せ字化
- `glab` CLIの設定ストアが、`gh` と同じサンドボックス・資格情報パス保護の対象に
- プラグインマーケットプレイスが `gitlab.com` のリポジトリURL（ネストされたサブグループを含む）をGitHubと同様にクローン可能に

**読者への影響**: 業務でGitLabを使っている場合、これまでGitHub前提だった機能の一部がそのまま使えるようになります。

## 新しく増えた環境変数

v2.1.233では、オプトインの環境変数が2つ追加されています。

- `CLAUDE_CODE_TOOL_MEMORY_LIMIT`: Linuxでのメモリcgroup対応。暴走したビルドがセッションを止めてしまうのを防ぐ用途とされています
- `CLAUDE_CODE_WEBFETCH_CACHE_TTL_MS`: WebFetchのセッションURLキャッシュのTTLを設定（既定値は従来どおり15分）

## まとめ

今回の目玉は、タスク管理ツールが新しいモデルで既定オフになったことです。機能の削除ではなく、モデル側の能力向上を前提にコンテキストを節約する変更、という位置づけです。

いま確認しておくとよいのは次の3点です。

- 作業の進捗をタスクリストで追う運用をしているなら、`CLAUDE_CODE_ENABLE_TODO_TOOLS=1` を設定するか、表示なしで運用するかを決める
- Agent SDKで `TodoWrite` / `TaskCreate` の `tool_use` を監視しているなら、対象モデルで空にならないか確認する
- Windowsで使っているなら、v2.1.233まで上げて資格情報漏えい経路の修正と承認プロンプトの回帰修正を取り込む
