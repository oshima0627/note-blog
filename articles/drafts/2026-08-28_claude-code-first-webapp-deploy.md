## この記事の成果物は、実際に公開されています

先に完成物をお見せします。

https://jikyu-log.oshima6-27.workers.dev

「時給ログ」という1画面のアプリです。作業内容と時間と報酬を入力すると、その週の合計作業時間と、実質時給を計算します。データはブラウザの中に保存されるので、サーバーもデータベースも要りません。

このURLは、この記事を書くために私が実際に手順を通して公開したものです。読み終えたとき、あなたも同じように「他人に見せられるURL」を1本持っている状態になります。

そして重要なのはここです。この記事に書いてある手順は、すべて私が実機で実行して、その出力を確認したうえで書いています。想像で書いた手順は入っていません。通していない部分は「未検証」と明記します。

## 第0章 先にお金の話をします

技術記事は費用の話を後回しにしがちですが、ここを曖昧にすると途中で止まります。

まず、いちばん重要な事実から。

Claude Code は、Claudeの無料プランでは使えません。

公式ドキュメントに「Claude Code requires a Pro, Max, Team, Enterprise, or Console account. The free Claude.ai plan does not include Claude Code access.」と明記されています。無料で試すことはできない、と最初に理解しておいてください。

Claude の個人向けプランの価格は、公式の料金ページで次のとおりです（2026年8月28日時点・ドル表記）。

・Free：0ドル。Claude Code は含まれません
・Pro：月額20ドル。年払いにすると実質17ドル（200ドルを前払い）。Claude Code が含まれます
・Max：月100ドルから。Claude Code が含まれます

つまり、最低ラインは Pro の月20ドルです。

一方で、公開する側の費用はゼロで始められます。この記事では Cloudflare Workers を使いますが、公式の料金ページによると無料プランで1日10万リクエストまで使えます。さらに「Requests to static assets are free and unlimited」と明記されていて、今回作るような静的なファイルへのリクエストは無料かつ無制限です。有料プランは月5ドルからですが、最初の1本では不要です。

まとめると、初期費用は Claude の月20ドルだけです。ドメインを買わなければ、それ以外はかかりません。

## 第1章 Claude Code を入れる（Windows）

Windows では、ターミナルを開いてコマンドを1行実行するだけです。

まず、いま自分がどちらのターミナルにいるかを確認します。公式ドキュメントに見分け方が書かれていて、行頭が「PS C:\」で始まっていれば PowerShell、「PS」が無く「C:\」だけなら CMD です。ここを間違えるとエラーになります。

PowerShell の場合はこれです。

irm https://claude.ai/install.ps1 | iex

CMD の場合はこれです。

curl -fsSL https://claude.ai/install.cmd -o install.cmd && install.cmd && del install.cmd

WinGet を使っている方はこちらでも入ります。

winget install Anthropic.ClaudeCode

macOS・Linux・WSL の場合は、公式ページに次のコマンドが載っています（私は未検証です）。

curl -fsSL https://claude.ai/install.sh | bash

なお、公式ドキュメントには「PowerShell と CMD を取り違えたときのエラーメッセージ」まで書かれています。「The token '&&' is not a valid statement separator」が出たらPowerShellにいる、「'irm' is not recognized」が出たらCMDにいる、という判定です。慌てずにもう一方のコマンドを試してください。

### Node.js は要りません

ここは誤解が多いところです。

公式のインストーラー（上のコマンド）で入れる場合、Node.js は必要ありません。ネイティブのバイナリが入るだけです。npm 経由でも入れられますが、その場合は Node.js 22以上が必要になります。未経験の方は、上のコマンドをそのまま使ってください。

### Git for Windows は任意ですが、入れておくと楽です

公式ドキュメントによると、Git for Windows は必須ではありません。ただし入れておくと Claude Code が Bash ツールを使えるようになります。無い場合は PowerShell のツールを使う動きになります。

どのみち後で公開するときに Git を使うので、この段階で入れておくのをおすすめします。

### 入ったか確認する

インストールが終わったら、ターミナルで次を実行します。

claude --version

私の環境では次のように出ました。

2.1.233 (Claude Code)

バージョン番号が出れば成功です。うまく動かないときは、次のコマンドで診断が見られます。

claude doctor

これはセッションを開始せずに、インストール状態と設定ファイルの問題だけを表示してくれます。

### ターミナルがどうしても苦手な方へ

公式にデスクトップアプリが用意されていて、ターミナルを使わずに Claude Code を利用できます。Windows 版もあります（有料プランが必要な点は同じです）。まずGUIで慣れてから、あとでターミナルに移るという順番でも問題ありません。

## 第2章 何を作るかを決める

未経験の方が最初に止まるのは、実は技術ではなく「何を作ればいいか分からない」です。

ここには型があります。最初の1本は、次の3条件を全部満たすものにしてください。

・自分が実際に困っていること
・データを他人と共有しなくていいこと
・画面が1つで終わること

この3つを満たすと、サーバーもログイン機能もデータベースも要らなくなります。要らないということは、詰まる場所が消えるということです。未経験者にとって、これが最大の設計判断です。

今回作る「時給ログ」は、この条件を満たしています。

・困りごと：副業をしていると、実際の時給が分からなくなる
・共有不要：自分の記録なので、自分の端末に保存されていればいい
・1画面：入力フォームと、今週の集計と、履歴だけ

仕様を言葉にすると、こうなります。

日付、内容、作業時間（分）、報酬（円）を入力して記録する。今週分を合計して、合計作業時間と実質時給を表示する。過去の記録は一覧で表示し、1件ずつ削除できる。データはブラウザに保存し、閉じても残る。

この段落くらいの粒度で書けていれば、Claude Code は作れます。

## 第3章 作らせる

作業用のフォルダを作って、そこでターミナルを開き、次を実行します。

claude

対話が始まったら、さきほど言葉にした仕様をそのまま伝えます。ただし、未経験の方は次の3点を必ず足してください。ここが、出てくるコードの扱いやすさを決めます。

・ビルド不要の構成にしてほしい、と指定する
・ファイルを3つに分けてほしい、と指定する
・データの保存先を指定する

具体的には、こう書きます。

「ビルド作業が要らない、HTMLとCSSとJavaScriptの3ファイルだけの構成で作ってください。データはブラウザのlocalStorageに保存してください。次の仕様です。（ここに仕様）」

なぜこう指定するのかというと、指定しないと Claude Code は React などのフレームワークを選ぶことがあるからです。それ自体は悪くないのですが、未経験の1本目では、インストールとビルドという2つの詰まりどころが増えます。最初は増やさないほうがいいです。

出てくるファイルは3つです。役割はこうです。

・index.html：画面に何を置くか（入力欄、ボタン、表示場所）
・style.css：見た目（色、余白、文字の大きさ）
・app.js：動き（計算する、保存する、消す）

私の環境で実際に生成されたファイルのサイズは、index.html が939バイト、style.css が792バイト、app.js が1,991バイトでした。合計3,722バイトです。「アプリ」と聞いて身構えるほどの量ではありません。

## 第4章 ローカルで動かして、確認する

書けたら、自分のパソコンの中だけで動かして確認します。

作ったフォルダで、次を実行します。

npx serve -l 5173 .

初回は serve というツールを取りに行くので、インストールしてよいかの確認が出ます。許可して少し待ってください。次のように出れば起動しています。

INFO Accepting connections at http://localhost:5173

ブラウザで http://localhost:5173 を開いてください。

### 「動いた」を、感覚で判定しない

ここが、未経験の方にいちばん伝えたい部分です。

画面が出ただけでは「動いた」ではありません。先に「何がどうなれば正解か」を1つ決めて、それを確かめてください。

今回はこう決めました。

作業時間150分、報酬5,000円を1件入力したら、実質時給が2,000円と表示されること。

5,000円 ÷ 150分 × 60分 = 2,000円 なので、これが正解です。

実際に入力したところ、画面にはこう出ました。

今週の作業 2.5 時間 / 報酬 5,000 円
実質時給 2,000 円

合っています。ここまで来て初めて「動いた」です。

この「正解を先に決めてから確かめる」やり方は、この先ずっと効きます。Claude Code に修正を頼むときも、「うまく動かない」と伝えるより「150分5,000円を入れたら2,000円になるはずが、0円になる」と伝えたほうが、はるかに速く直ります。

## 第5章 公開する（Cloudflare Workers）

ローカルで動いても、それは自分にしか見えていません。ここから、誰でも見られるURLにします。

今回は Cloudflare Workers を使います。理由は3つです。無料枠で始められること、静的ファイルへのリクエストが公式に無料かつ無制限とされていること、そしてコマンド1つで公開できることです。

### ファイルを1つのフォルダにまとめる

公開するファイルを public というフォルダにまとめます。構成はこうなります。

（プロジェクトフォルダ）
　├ public
　│　├ index.html
　│　├ style.css
　│　└ app.js
　└ wrangler.jsonc

### 設定ファイルを1つ置く

wrangler.jsonc というファイルを作って、次の内容にします。

{
　"name": "jikyu-log",
　"compatibility_date": "2026-08-28",
　"assets": {
　　"directory": "./public"
　}
}

name は公開URLの一部になります。compatibility_date は、動作の基準にする日付です。新しめの日付を入れておきます。

公式ドキュメントによると、静的ファイルだけを公開する場合、main（プログラム本体の指定）は不要です。この3行だけで足ります。

### 公開する

次を実行します。

npx wrangler deploy

Cloudflareのアカウントが必要です。未ログインの状態だと、ここでログインを求められます（私の検証環境はすでにログイン済みだったため、この画面自体は確認していません）。

ログイン済みなら、次のように出ます。実際の出力です。

✨ Read 3 files from the assets directory
🌀 Found 3 new or modified static assets to upload.
+ /style.css
+ /index.html
+ /app.js
✨ Success! Uploaded 3 files (1.01 sec)
Uploaded jikyu-log (4.06 sec)
Deployed jikyu-log triggers (1.91 sec)
　https://jikyu-log.oshima6-27.workers.dev

最後の行があなたのURLです。所要時間は、ファイルのアップロードから公開まで合計で約7秒でした。

URLの形は次のようになります。

https://（wrangler.jsoncのname）.（あなたのアカウントのサブドメイン）.workers.dev

これで公開は終わりです。ブラウザで開けば、他の人にも同じ画面が見えます。

## 第6章 公開してから効いてくる挙動（実測）

公開後、実際にどう振る舞うのかを確かめました。ここは未経験の方が驚くところなので、実測値を出します。

トップページにアクセスすると、HTTP 200 が返りました。CSSとJavaScriptも同じく200です。

面白いのはここからです。

/index.html にアクセスすると、HTTP 307 が返り、/ にリダイレクトされました。つまり、ファイル名を含むURLは、自動的にきれいなURLに寄せられます。

存在しないパス（例：/sonzai-shinai）にアクセスすると、HTTP 404 が返りました。

このあたりは自分で設定しなくても、そういう動きになります。最初のうちは触らなくて構いません。

### ファイルの読み込みパスについて

HTMLの中でCSSやJavaScriptを読み込むとき、書き方が2通りあります。

・相対パス：./style.css
・絶対パス：/style.css

今回のように、サイトがサブドメインの直下に置かれる場合は、どちらでも動きます。ただし、将来ホスティング先を変えて、サイトが「/なにか/」の下に置かれる構成になると、絶対パスは壊れます。

実際に検証しました。サイトを /jikyu-log/ の下に置いた状態で、相対パスの ./style.css は HTTP 200 でしたが、絶対パスの /style.css は HTTP 404 になりました。「ローカルでは見た目が出ていたのに、公開したらデザインが消えた」の正体は、ほぼこれです。

迷ったら相対パス（./ から始める形）にしておいてください。壊れる場面が減ります。

## 第7章 直して、出し直す

公開して終わりではありません。直して出し直すループが作れて、初めて「運用できる」状態です。

流れは3ステップです。

1. Claude Code に修正を頼む（ローカルのファイルが書き換わる）
2. npx serve でローカルで確認する
3. npx wrangler deploy でもう一度公開する

2回目以降のデプロイは、変更されたファイルだけがアップロードされます。数秒で終わります。

Git を使っているなら、公開の前にコミットしておいてください。おかしくなったときに戻せます。

git add -A
git commit -m "何を変えたか"

### 未経験者が必ず踏むGitの落とし穴

私の環境で git init を実行したところ、作られた既定のブランチ名が master でした（Git 2.49.0.windows.1）。一方で、いまのGitHubなどは main を前提にしている場面が多いです。

食い違うと、後でリモートに繋ぐときに混乱します。最初に揃えておきましょう。

git branch -M main

これでブランチ名が main になります。

## 第8章 ここから、どう収益につなげるか

公開URLを持つと何が変わるのか。ここを構造として理解しておくと、次の一手を間違えません。

### 変わるのは「証明できるかどうか」です

未経験からの副業で最初に詰まるのは、スキルではなく証明です。「できます」と言うだけの人と、「これを作って公開しました、URLはこれです」と出せる人では、相手の判断材料がまったく違います。

1本公開したあなたは、後者になれます。この差は、案件に応募するときも、知人から仕事を頼まれるときも効きます。

なお、案件単価の相場については、出典の取れる公的な数値を私は確認できていません。ですのでこの記事では金額を書きません。相場を語る記事は多いですが、根拠のない数字を覚えても判断は良くなりません。

### 作ったものを売る場所と、実際に引かれる手数料

自分で作ったものを直接売る道もあります。ここは手数料が公開されているので、正確に書けます。

noteの公式ヘルプセンターに記載されている手数料は次のとおりです（2026年8月28日時点）。

事務手数料（購読者の決済手段によって変わります）

・クレジットカード決済：5%
・携帯キャリア決済：15%
・PayPay決済：7%
・Amazon Pay決済：7%
・noteポイントでの決済：10%
・PayPal決済：6.5%

プラットフォーム利用料（売上金額から事務手数料を引いた金額に対して）

・有料記事、有料マガジン、チップ、メンバーシップ：10%
・定期購読マガジン：20%

振込手数料

・270円（1回の振込につき1回のみ）

公式に載っている計算例をそのまま引くと、1,000円の有料記事がクレジットカード決済で1件売れた場合、事務手数料が50円、プラットフォーム利用料が95円、振込手数料が270円で、振込金額は585円になります。

ここで気づいてほしいのは、振込手数料の270円が固定だということです。少額でこまめに振り込むほど、手取りの比率が下がります。ある程度まとめてから受け取るほうが有利、という単純な話です。

### 順番を間違えないでください

最後に、いちばん大事なことを書きます。

作れるようになったからといって、すぐに売れるわけではありません。売れるかどうかは、作る力ではなく「誰の何を解決したか」で決まります。

ですので順番はこうです。まず1本公開する。次に、それを使ってくれる人を1人見つける。その1人が繰り返し使う理由を確かめる。そこまで来てから、売る形を考える。

1本目のアプリが自分用でいい理由も、ここにあります。自分が毎日使うものは、使われる理由が分かっている数少ないものだからです。

## 第9章 詰まったときの対処

実際に手順を通す中で、詰まりやすい箇所を整理しておきます。

claude というコマンドが見つからない、と言われる

ターミナルを一度閉じて開き直してください。それでも駄目なら claude doctor を実行して診断を見てください。

インストールコマンドでエラーが出る

PowerShell と CMD を取り違えている可能性が高いです。行頭の「PS」の有無で判定して、対応するコマンドを使ってください。

npx serve でブラウザに何も出ない

URLを確認してください。表示されたポート番号（例では5173）と、開いているURLが一致している必要があります。

公開したらデザインが消えた

第6章のパスの話です。CSSの読み込みを ./style.css の形にしてください。

Claude Code の出したコードが動かない

「動きません」ではなく、「何を入れたら、何が出るはずが、何が出たか」を伝えてください。第4章で決めた正解の条件が、そのまま報告文になります。
