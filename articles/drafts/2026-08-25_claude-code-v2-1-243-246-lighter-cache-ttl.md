# Claude Code v2.1.243〜246：軽量化とキャッシュTTL設定

この記事は2026年8月25日時点の情報です。仕様は更新が速いため、最新は公式チェンジログでご確認ください。

この記事でわかること

- 8月25日に公開された3バージョン（v2.1.243 / 245 / 246）の中身
- ダウンロードサイズとメモリ使用量が下がったこと、その具体的な数字
- プロンプトキャッシュの保持時間（TTL）を自分で選べるようになったこと

## 8月25日に3バージョンが公開されました

Claude Code公式チェンジログによると、2026年8月25日に v2.1.243、v2.1.245、v2.1.246 の3バージョンが公開されました。直前の v2.1.240（8月22日）と v2.1.241（8月23日）はどちらも「Bug fixes and reliability improvements」の1行だけでしたが、今回は中身のある更新が並んでいます。

なお公式チェンジログのページに v2.1.242 と v2.1.244 の見出しはありません。ただし設定ドキュメントには「v2.1.242以降が必要」という記述がある項目があるため、番号自体は存在しているようです。

## 1. 起動が速く、メモリが軽くなりました

v2.1.243 の「Improved」項目に、動作の軽さに関する変更がまとまっています。数字が出ているものを挙げます。

- ネイティブ版インストールと自動更新のダウンロードサイズが、バイナリのzstd圧縮により Linux x64 で約340MBから約75MBになった
- ネイティブ版のメモリ使用量が、コードを一括で常駐させず必要時に読み込む方式に変わり、1セッションあたりおよそ40〜70MB減った
- ネイティブバイナリ自体が約2MB小さくなった（内蔵スキル・プロンプトのテキストを詰めたため）
- 長時間セッションのピークメモリが改善された（ヒープが大きくなると早めにガベージコレクションするようになった）
- 起動時間が改善された。サンドボックスとMCPの立ち上げが最初の描画をブロックしなくなり、ワークフロー探索・設定・トラストストアの処理も軽くなった

読者への影響として大きいのは、自動更新のたびに数百MBを落としていた環境です。回線が細い場所やCI、コンテナのイメージ更新では体感差が出ると考えられます（この点は筆者の見方で、公式は数字のみ提示しています）。

なお v2.1.243 では、Ctrl+Oやフルスクリーンのトランスクリプト表示で、セッションが長くなるほどメモリが増えていた問題も修正されています。

## 2. プロンプトキャッシュのTTLを自分で選べます

今回いちばん実務に効くのが、これだと思います。

Claude Codeは毎ターン、会話の全履歴を送り直しています。プロンプトキャッシュは、その「前回と同じ部分」を再処理せずに済ませる仕組みです。キャッシュは一定時間アクセスがないと消え、消えた後の1ターンは全文を処理し直すため、遅く・高くなります。

この保持時間（TTL）には5分と1時間の2種類があり、v2.1.243 で `promptCacheTtl` と `subagentPromptCacheTtl` の2つの設定が追加されました。公式ドキュメントによると、いずれも v2.1.242以降が必要で、値は `5m` か `1h` のみ、それ以外は無視されます。環境変数 `CLAUDE_CODE_PROMPT_CACHE_TTL` / `CLAUDE_CODE_SUBAGENT_PROMPT_CACHE_TTL` でも指定できます。

既定値は、課金の形で分かれます。公式ドキュメントの説明はこうです。

- Claudeサブスクリプションでプラン内の使用量に収まっている場合：メインの会話は1時間。それ以外（サブエージェント、ワークフロー、compact、セッション名の生成など）は5分
- 使用量クレジット、APIキー、クラウドプロバイダ経由の場合：メインの会話もそれ以外も5分

つまり、APIキーやBedrock・Vertex経由で使っている人は、これまで一律5分でした。`promptCacheTtl` を `1h` にすると、メインの会話だけ1時間になります。サブエージェント側も伸ばしたいなら `subagentPromptCacheTtl` を別に指定します。

ここは注意が必要です。1時間TTLはキャッシュ書き込みの単価が高くなります。公式ドキュメントも「5分以上あかない短い集中作業では、長い保持時間が使われないまま書き込み単価だけ上がるので高くつく」と明記しています。席を離れて戻る使い方が多い人向けの設定、という位置づけです。

また、サブスクリプションでもプランの上限を超えて使用量クレジットに入ると、メインの会話は自動的に5分に落ちます。そこで1時間を維持したい場合は、自分で `promptCacheTtl` を指定する必要があります。

制約も書かれています。1時間TTLは Claude apps gateway 経由では使えません。Amazon Bedrock では、キャッシュ対応そのものや1時間TTLの可否がモデルによって異なります。

## 3. `/usage` に Loops の内訳が出ます

v2.1.243 で、`/usage` に Loops の内訳が追加されました。ループごとの実行回数、合計トークン、1回あたりのトークン、最終実行が表示されます。公式チェンジログは「暴走したり、やたらと喋る `/loop` タスクを見つけやすくするため」と説明しています。

定期実行を仕込んでいる人は、まずここを見るのが早そうです。同じ v2.1.243 では、`/loop` で「やることがない」起動が連続したとき、ターミナル上で1行にまとめられる変更も入っています。

## 4. 権限まわりの警告と、認証情報の送信先の修正

v2.1.246 は修正が中心ですが、権限とセキュリティに関わるものが含まれます。

- Bashの許可ルールで、サブコマンドの前にワイルドカードを置いた書き方（例：`Bash(git * main)`）に対して、起動時に警告が出るようになりました。この書き方は、サブコマンドの前に差し込まれたオプションにも一致してしまうためです
- `/permissions` に Auto mode タブが追加され、autoモードの分類ルールを確認・編集できるようになりました
- サードパーティのゲートウェイ（`ANTHROPIC_BASE_URL`）向けに設定したAPIキーが、Anthropic宛てのテレメトリ／メトリクス送信にも付いていた問題が修正されました。認証情報は、その認証情報が属するホストにのみ送られるようになりました
- 不正な形式のBashコマンド（末尾に `&&` や `||` が残っているもの）は、必ず承認を求めるようになりました
- サンドボックスの「Network request outside of sandbox」の確認待ちの間、`Notification` フックが発火しなかった問題が修正されました

自作のフックやゲートウェイ構成で運用している場合は、1つ目と3つ目を確認しておくとよさそうです。

## 5. Linuxのglibc 2.44でのクラッシュ修正

v2.1.245 は1行だけの更新で、glibc 2.44 を採用しているLinuxディストリビューションでの起動時クラッシュの修正です。公式チェンジログは例として Arch Linux、CachyOS、Fedora Rawhide を挙げています。該当環境で起動しなくなっていた人は、更新で直る可能性があります。

## 更新するときに知っておくこと

Claude Codeのバージョンを上げると、システムプロンプトやツール定義が変わるため、更新後の最初のリクエストはキャッシュを一から作り直します。公式ドキュメントはこれを想定内の挙動として説明しています。自動更新はバックグラウンドでダウンロードし、セッション中ではなく次回起動時に適用されるため、作業中に急に遅くなることはありません。

注意点として、長い会話を再開する場合は履歴全体が別のシステムプロンプトの後ろに来るため、キャッシュが効かず、その1ターンが最も高くなる可能性があると明記されています。更新直後は、長いセッションを再開するより新しく始めるほうが無難です。

このほか v2.1.243 では、APIが応答を返し始めないまま10分以上セッションが沈黙する問題も修正されました。現在は約3分でタイムアウトし、1回リトライしたうえで `API Error: No response from API` を表示します。
