# Claude Code v2.1.234：上限リセット後に自動で再開されます

2026年8月17日時点の情報です。Claude Code の v2.1.234 が公開されました。公式チェンジログをもとに、日常的に使う人への影響が大きい変更を整理します。

## この記事でわかること

- 使用量上限に当たったセッションが、リセット後に自動で続きから動くようになったこと
- 作業中でも `/permissions` や `/add-dir` を開けるようになったこと
- 権限・シークレット表示まわりの修正が複数入っていること

## 1. 使用量上限のリセット後、セッションが自動で続く

今回いちばん体感が変わるのはここです。公式チェンジログには、claude.ai の使用量上限がリセットされたときに Claude Code がセッションを自動で継続するようになった、と記載されています。無効にしたい場合は `/config` の「Continue automatically at usage limit」で切り替えます。

**読者への影響**：これまでは上限に当たると作業が途中で止まり、リセット時刻に自分で戻って再開する必要がありました。長い実装やリファクタの途中で止まると、文脈を思い出すところからやり直しになりがちです。今回の変更で、席を外している間にリセットを跨いでも作業が進む可能性があります。

一方で、放置している間に自動で続きが動くということでもあります。権限モードを緩めたまま長時間のタスクを走らせている場合は、意図しない実行が起きないか一度確認しておくのが安全だと筆者は考えます。オフにしたい人は `/config` から切れます。

## 2. `/permissions` と `/add-dir` が作業中に開ける

Claude が作業している最中でも `/permissions` を開けるようになり、ルールの変更はそのターンの残りから適用されます。`/add-dir <path>` も作業中に使えるようになりました。加えて、フルスクリーンTUIでは `/add-dir`・`/autocompact`・`/theme`・`/help`・`/config`・`/advisor` のダイアログをターンの途中で開けます。

**読者への影響**：許可を足すためにいちいちターンの終了を待つ、という待ち時間が減ります。作業を止めずにディレクトリを追加できるのも、モノレポや複数リポジトリをまたぐ作業では効きます。

## 3. `claude-api` スキルのコンテキスト消費が大幅に減少

組み込みスキル `claude-api` の読み込みコストが、約20万トークン超から約2.5万トークンへ削減されたと記載されています。参照ドキュメントを必要になった時点で読み込む方式に変わったためです。

**読者への影響**：Claude API まわりの作業でこのスキルを使うと、これまではコンテキストの多くを最初に持っていかれていました。長いセッションでの圧縮（コンパクト）の発生が減ることが期待できます。

## 4. セキュリティと権限まわりの修正

前バージョン v2.1.233 では、Windows の NT デバイスプレフィックス（`\??\`）を使ったパス表記が UNC パス検証をすり抜け、NTLM 認証情報の漏洩につながりうる問題が修正されていました。v2.1.234 ではその対策範囲が広がり、リモートファイル読み取り・セッション復元・CLAUDE.md のインクルード・ワークフロースクリプト・ファイルアップロードでも NT名前空間パスを拒否するようになっています。

権限まわりでは、次の修正が入りました。

- バックグラウンドのサブエージェントの権限プロンプトに答えたとき、セッション単位の回答（拒否を含む）が破棄されていた問題の修正
- 非常に長いセッションで会話が圧縮された後、auto モードがサンドボックス済みコマンドのネットワークアクセスを繰り返し再確認して拒否していた問題の修正
- MCP の診断表示が解決済みのシークレットを出力していた問題の修正。スコープ競合の警告は設定された `${VAR}` の形で表示され、接続失敗の詳細はサーバーのオリジンのみを表示するようになりました
- 権限プレビューの認証情報マスクが、承認する側からコマンド・パス・送信先を隠してしまいうる問題の修正

**読者への影響**：3つ目と4つ目は、承認画面や診断表示の「見え方」に関わる修正です。シークレットが出てしまう方向のミスと、逆に承認判断に必要な情報が隠れてしまう方向のミスの両方が塞がれた形になります。Windows で使っている人は、v2.1.233 と合わせて更新しておく価値があります。

## 5. そのほかの変更

- GitLab のリモートと認証済みの `glab` CLI があるリポジトリで、フッターとステータスラインにマージリクエストのバッジ（`MR !N`、ドラフト/保留/グリーンの状態付き）が表示されます
- 自動生成されるセッションタイトルが、依頼文を言い換えた文章ではなく短く具体的な名前（例：「Login button bug」）になりました
- トランスクリプト上で、自分が送ったプロンプトも返信と同じようにマークダウンとして描画されます
- `/goal` が、認証失効・残高切れ・コンテキスト超過などの復帰不能なエラーでターンが終わったとき、有効なまま残らず通知とともに解除されます。またバックグラウンドタスクの待ちが30分以上続くと Claude が様子を見に行くようになりました（`CLAUDE_CODE_GOAL_CHECKIN_MINUTES=0` で無効化）
- `/config` から「Default teammate model」設定が削除されました。エージェントチームのメンバーは、起動時に指定がなければリーダーのモデルを使います
- Claude に対し、アカウントのメールアドレスは本人の識別にのみ使い、依頼がない限り無関係なサービスに送らないよう指示が入りました

## 更新方法

`claude update` で更新できます。バージョンは `claude --version` で確認します。仕様や設定名は変わることがあるため、最新は公式チェンジログで確認してください。
