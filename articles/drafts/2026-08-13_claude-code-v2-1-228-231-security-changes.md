# Claude Code更新：claude.ai同期スキルの権限が縮小されました

※2026年8月13日時点の情報です。仕様は変わりやすいため、最新は公式changelogでご確認ください。

## この記事でわかること

- Claude Code v2.1.228で、claude.aiから同期されたスキルの実行権限が絞られたこと
- v2.1.229で `/commit-push-pr` が危険なgitフラグを自動承認しなくなったこと
- 逆に緩和された点（Writeツールの上書きルール）と、そこで気をつけること

## claude.ai同期スキルの権限が縮小されました

2026年8月11日公開のClaude Code v2.1.228で、claude.aiから同期されたスキルの扱いが変更されました。公式changelogの記載は次のとおりです。

- ローカルのコマンドやMCPプロンプトを**シャドーイング（同名で上書き）しなくなった**
- スキルの説明文（description）が**サニタイズされ、同期スキルであるとラベル付けされる**ようになった
- 自分のマシン上では、スキル本文の `!` コマンド実行と `@` によるファイル展開が**行われなくなった**

Claude Codeのスキルは、`!` を使ったシェルコマンドの埋め込みや `@` によるファイル参照を本文に書けます。これはローカルで自分が書いたスキルには便利な仕組みですが、claude.ai側から同期されてくるスキルにも同じ権限があると、話が変わります。

技術系メディアのClaudingは2026年8月12日付の記事で、この変更前の状態を「同期スキルがローカルコマンドをシャドーイングでき、シェルコードを実行できた」と整理し、攻撃面（attack surface）として説明しています。つまり、自分が打ったつもりのコマンド名で別のものが動く余地があった、という指摘です。

**読者への影響**: claude.aiのスキル同期を使っている場合、この更新でローカル側が優先されるようになります。同名のスキルとローカルコマンドが共存していた人は、v2.1.228以降で呼ばれる対象が変わる可能性があります。挙動が変わったと感じたら、まずここを疑うとよいと思います（筆者の見方）。

なお、この変更が具体的な被害報告を受けたものかどうかについて、公式の説明は確認できませんでした。

## `/commit-push-pr` が危険なgitフラグを自動承認しなくなりました

2026年8月12日公開のv2.1.229では、`/commit-push-pr` の挙動が変わりました。公式changelogによると、`--force` `--amend` `--no-verify` などの危険なフラグを含むgit/ghコマンドは、**自動承認の対象から外れました**。

これらのフラグは、それぞれリモート履歴の上書き、直前コミットの書き換え、コミットフックのスキップにあたります。いずれも「実行されてから気づくと戻しにくい」種類の操作です。

**読者への影響**: これまで `/commit-push-pr` が黙って通していた操作で、承認プロンプトが出るようになります。CI連携やヘッドレス実行で `/commit-push-pr` を組み込んでいる場合、承認待ちで止まる可能性があるため、動作を一度確認しておくことをおすすめします。

## Writeツールの上書きルールは緩和されました

同じv2.1.229には、逆方向の変更もあります。Writeツールについて、**新しいモデルはセッション中に読んでいない既存ファイルも上書きできる**ようになりました（Editツールのルールに合わせた形）。古いモデルでは従来どおり、先に読む必要があります。

これは手数を減らす変更ですが、「上書き前に必ず中身を読む」というガードが1つ外れた形でもあります。生成物ではない手書きの設定ファイルなどを扱う場面では、権限モードやサンドボックス設定側で担保しておく方が安全だと考えられます（筆者の見方）。

## サンドボックスのIPv6表記がfail-closedに

v2.1.229では、サンドボックスのネットワークドメイン指定も変更されています。公式changelogによれば、IPv6リテラルは `[::1]:443` のように**角括弧付きで書く形式**になり、あいまいな書き方は**fail-closed（通さない側に倒す）で扱われ、`/doctor` で指摘される**ようになりました。

**読者への影響**: 許可リストにIPv6リテラルを書いている場合、記法によっては通らなくなる可能性があります。`/doctor` を一度実行して確認しておくとよい箇所です。

## その他の安定性修正

v2.1.229は修正項目が多いリリースです。読者に関係しそうなものを挙げます。

- ストリーミング中に長い応答の一部が消え、二重に表示される不具合の修正
- ツール呼び出しの `glob` `file_path` `command` が文字列でない場合のクラッシュ修正（`--resume` 時も含む）
- 非常に狭いターミナル幅でのRangeErrorクラッシュ修正
- `/install-github-app` が生成するClaude Code Reviewワークフローが、レビューを投稿せずに完了してしまう不具合の修正

また、8月13日公開のv2.1.231では、Slackなど事前登録済みOAuthクライアントを使うサーバーで、MCPのOAuthサインインがリダイレクトURI不一致で失敗する不具合が修正されています。

## まとめ

今回の更新は、料金や既定モデルのような大きな変更ではありません。ただし方向性ははっきりしています。**外から来るもの（同期スキル）の権限は絞り、取り返しのつかない操作（force push等）は人に確認を戻す**という整理です。

いま確認しておくとよいのは次の3点です。

- claude.aiのスキル同期を使っているなら、ローカルコマンドと同名のスキルがないか
- `/commit-push-pr` を自動化に組み込んでいるなら、承認待ちで止まらないか
- サンドボックスの許可リストにIPv6リテラルがあるなら、`/doctor` が警告を出さないか
