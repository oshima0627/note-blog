# Claude Code v2.1.237/238：長時間セッションのメモリ肥大を修正

2026年8月20日時点の情報です。仕様は変わりやすいため、最新は公式のchangelog・ドキュメントでご確認ください。

Claude Code の v2.1.237 と v2.1.238 が、いずれも2026年8月20日に公開されました。v2.1.238 は修正・改善の件数が多い回ですが、実務でいちばん効くのは**長時間セッションでメモリが増え続ける問題の修正**です。あわせて、新しい出力スタイル「Concise」も使えるようになりました。

## この記事でわかること

- 長時間の対話セッションでメモリが増え続けていた問題と、その修正内容
- 新しい組み込み出力スタイル「Concise」と、出力スタイルが途中で元に戻る不具合の修正
- プラグイン・MCPの認証ヘッダー（headersHelper）まわりで加わった確認と制限

## 1. 長時間セッションのメモリ肥大を修正（v2.1.238）

公式changelogには、v2.1.238 の修正として次の記載があります。

> Fixed unbounded memory growth in long interactive sessions: subagent tool results are now released once they leave the recent display window

長い対話セッションで**メモリが上限なく増え続けていた**問題の修正です。サブエージェント（Agentツールで起動する下請けのClaude）のツール実行結果が、直近の表示範囲から外れた後も保持されたままになっていた、という内容です。修正後は表示範囲を抜けた時点で解放されます。

**読者への影響**：ターミナルを開きっぱなしにして半日〜1日同じセッションを使う、サブエージェントを多く走らせる、という使い方をしている方ほど恩恵があります。「作業が進むにつれて動作が重くなる」「メモリ使用量が戻らない」といった心当たりがあれば、更新で改善する可能性があります。

なお、この修正が対象にしているのは**サブエージェントのツール結果**です。長時間セッションで重くなる要因はほかにもあり得るため、更新後も改善しない場合は別要因を疑ってください。

## 2. 出力スタイル「Concise」が追加（v2.1.237）

v2.1.237 で、組み込みの出力スタイルに **Concise** が加わりました。公式ドキュメントの説明は次のとおりです。

> Claude leads with the result, skips preamble and narration, and keeps responses short by default, while doing the engineering work as thoroughly as in the Default style.

要点は以下です。

- 結果から先に述べ、前置きや実況のような説明を省く
- 既定では応答を短く保つが、**作業そのものの丁寧さはDefaultと変わらない**
- 説明や詳細を求めればきちんと答える
- エラー報告・セキュリティ警告・破壊的操作の確認は、省略せず全文を保つ

選び方は、ターミナルで `/config` を実行し「Output style」から選択します。設定ファイル（`.claude/settings.local.json` など）の `outputStyle` フィールドに直接書くこともできます。出力スタイルはセッション開始時に読み込まれるため、変更を反映するには `/clear` するか新しいセッションを開始します。公式ドキュメントには「Requires Claude Code v2.1.237 or later」と明記されています。

**読者への影響**：Claude Codeの応答が長すぎると感じていた方には有力な選択肢です。トークンの観点でも、公式ドキュメントは Explanatory / Learning が既定より長い応答を生む一方、**Conciseは逆方向に働く**と説明しています。

### 出力スタイルが途中で元に戻る不具合も修正（v2.1.238）

関連する修正が v2.1.238 に入っています。

> Fixed custom, project, and plugin output styles drifting back to the default voice mid-session

カスタム・プロジェクト・プラグインの各出力スタイルが、**セッション途中で既定の口調に戻ってしまう**問題の修正です。独自スタイルを作って使っていたのに、いつの間にか普段の応答に戻っていた、という経験がある方はこれが原因だった可能性があります。

## 3. プラグイン・MCPの認証ヘッダーに確認と制限（v2.1.238）

v2.1.238 では、プラグインマーケットプレイスとMCPに `headersHelper` という仕組みが関わる変更が複数入りました。`headersHelper` は、短命トークンなどのHTTPヘッダーをコマンドで生成する仕組みです。

changelogに記載されている内容を挙げます。

- URL形式のマーケットプレイスやカタログエントリの `headersHelper` が、カタログ取得と同一オリジンのアーカイブ取得にヘッダーを供給する
- カタログエントリの `headersHelper` は**インストールまたは更新のときだけ実行**され、実行するコマンドが提示されたうえで `claude plugin install/update` が `[y/N]` で確認する（`-y` で省略可）
- プロジェクトの `.mcp.json` にある `headersHelper`、およびプロジェクトや `--add-dir` のエージェントファイルにあるインラインMCPサーバーは、**そのフォルダの信頼ダイアログを承認済みであること**を要求する（`claude -p` でも同様）
- プロジェクトの `.mcp.json`・プラグイン・エージェントファイル由来の `headersHelper` は、**認証情報の環境変数を引き継がずに実行**される

**読者への影響**：他人のリポジトリをクローンして開く場面が該当します。外部から持ち込まれた設定が、確認なしにコマンドを実行したり手元の認証情報を受け取ったりする経路が狭まった、と読めます。筆者の見方では、プラグインやMCPを配布・共有している側は、自分の `headersHelper` が上記の条件下でも動くか一度確認しておくのが安全です。

## 4. そのほか、気づきやすい変更（v2.1.238）

- **Ctrl+L / Cmd+K の挙動変更**：フルスクリーンでは常に再描画のみになり、**2回押しで `/clear` するショートカットは削除**されました。1行のnvimターミナルで `/clear` が連発される問題への対応でもあります
- **`keybindingFlavor` 設定を追加**：`"readline"` にすると、プロンプト内の Ctrl+W がBashと同じく直前の空白まで削除します。既定の `"classic"` は従来どおりです
- **`claude mcp list` / `claude mcp get`**：無効化したサーバーに接続して死活確認するのをやめ、`⊘ Disabled` と表示するようになりました
- **セッション間メッセージ**：受信を拒否する設定のセッション宛て、または受信箱が溢れて破棄された場合に、送信側へ「拒否」「破棄」が伝わるようになりました（従来は成功扱いで消えていました）
- **一時ファイルの残留を修正**：Bashコマンドが強制終了・タイムアウト・中断されたときに `/tmp/claude-*-cwd` が残る問題
- **起動が速く**：macOSで `claude` の起動が早まり、自動アップデート確認は起動と競合しないよう約10秒後に実行されるようになりました
- **Remote Control の安定性**：ネットワークの一時的な不調でのログイン切れ、スマホやWebでのモデル選択がターミナルに反映されない、応答中に送ったメッセージがターミナル終了後に消える、といった問題が修正されています
- **プロンプトキャッシュの修正（v2.1.237）**：LLMゲートウェイやカスタムbase URLを使うセッションでキャッシュが効かない問題

## まとめ

v2.1.237/238 は、**長く使うほど効いてくる修正**が中心の回です。やることは2つです。

1. 更新して、長時間セッションでの重さが改善するか確かめる
2. 応答が冗長だと感じているなら `/config` から出力スタイル Concise を試す

Claude Code は自動更新に対応しているため、多くの環境では順次適用されます。すぐ試したい場合は手動で更新してください。
