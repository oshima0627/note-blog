# Claude Code v2.1.235：権限プロンプトの誤承認バグを修正

2026年8月18日時点の情報です。仕様は変わりやすいため、最新は公式のchangelog・ドキュメントでご確認ください。

Claude Code v2.1.235 が2026年8月18日に公開されました。今回は新機能よりも、**権限まわりの取り違えを直す修正**が実務上いちばん影響します。

## この記事でわかること

- 権限プロンプトで意図せず「セッション全体の編集許可」が付いていた不具合と、その修正内容
- 権限ダイアログの表示と「今後確認しない」の範囲が一致するようになった変更
- 入力欄のスペルチェックなど、その他の追加・改善点

## 1. Shift+Tabでコメント欄を閉じたつもりが、編集を承認していた

公式changelogには、v2.1.235の修正として次の記載があります。

> Fixed Shift+Tab inside the permission prompt's comment field approving the edit and granting session-wide edit permission instead of closing the field

権限プロンプト（ファイル編集などの許可を尋ねるダイアログ）には、コメントを書き添える欄があります。ここで Shift+Tab を押すと、**欄を閉じるのではなく編集を承認し、さらにそのセッション全体の編集許可まで付与されていた**、という不具合です。v2.1.235 で修正されました。

**読者への影響**：Shift+Tab は Claude Code で権限モードを切り替える際にも使うキーです。コメント欄を開いた状態でうっかり押していた場合、以降そのセッションでは編集許可の確認が出なくなっていた可能性があります。心当たりがある方は、更新後に `/permissions` で現在の許可ルールを一度確認しておくと安心です。

なお、これは「セッション内で編集が自動承認される」範囲の話です。changelogの記載はセッション単位の編集許可までで、設定ファイルへの永続化については触れられていません。

## 2. 権限ダイアログの表示と、実際に許可される範囲が一致するように

同じくv2.1.235の改善点です。

> Improved permission dialogs: display text and "don't ask again" options now always match what a grant would cover, and "don't ask again" is withheld when contents cannot be fully displayed

権限ダイアログの表示文と「今後確認しない（don't ask again）」の選択肢が、**実際に許可される範囲と常に一致する**ようになりました。加えて、内容を完全に表示できない場合には「今後確認しない」自体が出なくなります。

**読者への影響**：許可の判断は、ダイアログに書かれた内容だけを根拠に下すものです。表示と実際の範囲がずれていると、見えていないものまで許可してしまいます。中身が全部見えないときに恒久的な許可を選ばせない、という挙動は妥当な方向だと筆者は見ています。

関連して、ノートブックのセル削除・置換の承認ダイアログについても、既存セルの内容を読めなかったときに黙って省略するのではなく、**理由を表示する**よう修正されています。

## 3. スペルチェック設定の追加

新機能として、入力中のプロンプトのスペルミスに下線を引く `spellcheck` 設定が追加されました。判定には、環境にインストール済みの `aspell` / `hunspell` / `ispell` を使います。

**読者への影響**：任意設定（optional）なので、有効化しなければ従来どおりです。日本語入力が中心なら恩恵は限定的でしょう。なお、本稿の執筆時点では公式の設定ドキュメントの一覧にこの設定名の記載を確認できませんでした。設定方法は今後の公式ドキュメント更新をご確認ください。

## 4. そのほか、実務で効きそうな変更

v2.1.235 のchangelogから、影響が大きそうなものを挙げます。

- **バックグラウンドのクラウドセッションが軽くなった**：`/ultrareview` や `/autofix-pr` の実行中、イベントストリームを更新のたびに再走査・再描画しなくなり、メモリとCPUの使用量が改善されました
- **内蔵grepの改善**（macOS/Linuxのネイティブビルド）：問題のあるパターンでメモリを食い潰さず速やかに失敗するようになり、`-m N` と `-A/-C` の併用で正しい前後行が出るようになりました
- **コンテキスト上限エラーの説明が具体的に**：auto-compactが無効なときはその旨を伝え、`/config` から再有効化できると案内するようになりました
- **言語サーバーの切断・再接続でプロンプトキャッシュ全体が無効化される問題を修正**：セッション途中でLSPが落ちたときの影響が抑えられます
- **`SendMessage` の大きすぎるメッセージ**：セッション間で配送できないサイズのメッセージを、黙って落とさず最初に拒否するようになりました
- **タスクリストの表示**：未完了タスクが残るセッションを再開・再起動したとき、`ctrl+t` の展開表示が常に閉じた状態で始まる問題を修正
- **Agentツールのエラーが親切に**：general-purposeエージェントが使えないセッションで `subagent_type` を省略した場合、利用可能なエージェントを列挙したエラーが返るようになりました
- **表示まわりの修正**：ネストしたMarkdownリストの depth 3以上でのずれ、複数行プロンプトでの入力ハイライトのずれ、応答中に実行したスラッシュコマンドでHTMLエンティティがそのまま表示される問題など
- **Vimモード**：詳細トランスクリプト（ctrl+o）の切り替えやパネルを閉じた際に、NORMALモードとカーソル位置が保持されるようになりました
- **ダイアログ操作**：矢印キーとEnterを素早く連打したとき、直前にハイライトされていた選択肢ではなく、移動先の選択肢が選ばれるようになりました
- **VS Code**：Claudeのパネルが複数あるウィンドウの復元・再読み込み時に、タブ間でフォーカスが勝手に移る問題を修正

## まとめ：更新して、許可ルールを一度見直す

v2.1.235 は派手な新機能はありませんが、**「自分が何を許可したか」の正確さ**を取り戻す修正がまとまっています。Claude Codeは自動更新に対応しているため（changelogにもバックグラウンド自動更新への言及があります）、多くの環境では順次適用されます。

更新後にやることは2つだけです。バージョンが上がっているか確認すること、そして `/permissions` で意図しない許可が残っていないか見ておくことです。

（本文中の「筆者の見方」以外は、すべて下記の一次情報にもとづく事実です。）
