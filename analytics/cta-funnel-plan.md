## 貼るCTAの型

```

（記事の締めから自然につながる1文）

▼ まず1本試すなら（500円）
https://note.com/oshima0627/n/<入口の key>

▼ 副業として月10万円を目指す全体像（1,980円）
https://note.com/oshima0627/n/nf6dc3eb8e78d

```

URLを単独行に入力して Enter すると note が埋め込みカードに変換する。

## 実施手順（note エディタ／検証済み）

1. `https://editor.note.com/notes/<key>/edit/` を開く（**数値ID ではなく key**。
   数値IDのURLはエディタが空で立ち上がり、保存すると記事を壊す恐れがある）
2. 7〜8秒待つ。本文が出るまで**絶対に保存しない**
3. 本文の**最終行を実際にマウスでクリック**する → `End` → `Return` を2回
4. `getSelection()` の親チェーンが `P` 直下（BLOCKQUOTE/LI でない）ことを確認する
5. CTA を type で入力。URL行のあとは4秒待って埋め込みカードの生成を待つ
6. 「公開に進む」→「更新する」
7. `/api/v3/notes/<key>` を叩いて `ctaLinks>=2` と `status:"published"` を確認

## 落とし穴（実際に踏んだ）

- **JavaScript で `getSelection()` にカーソルを置いてから type すると壊れる。**
  Enter が全部無視されて1行に連結され、英数字が脱落する
  （「▼ まず1本試すなら（500円）」→「▼まず本試すなら（円）」）。
  **必ず実際のマウスクリックでフォーカスを取ること。**
  やらかしたら Ctrl+Z を40回。公開版は 更新する を押すまで無傷
- 記事末尾が引用ブロックや箇条書きのことが多い。`Return` 2回で抜けてから書く
- エディタ右上の文字数カウンタは遅延する。判定には使わない。
  `document.querySelector('.ProseMirror').innerText` を見る
- 「更新する」でも**公開日は変わらない**（検証済み）

## 新規記事の公開手順（2026-08-27 に確立）

noteエディタは癖が強い。以下の順でないと壊れる。

1. `note.com/notes/new` を開く（新規下書きが `editor.note.com/notes/<key>/edit/` に作られる）
2. タイトル欄をクリックして `type`
3. 本文欄を**実クリック**でフォーカス
4. 本文は **`ClipboardEvent('paste')` で一括投入**する。
   `text/html` に `<p>` の連続を入れる。段落が正しくブロック分割される
   - **`type` + Enter の連打はダメ。** すべて `<br>` になり1段落に潰れる
   - **h2/h3 はペーストで落とされる**（Pに変換される）。見出しは後から付ける
5. 見出しは **選択 → フローティングツールバーの「見出し」→「大見出し」**。
   - ツールバーは選択直後にフェードインする。**triple_click と同じバッチでスクショを撮り、
     その座標を使う**。ref は再描画で無効になりやすい
   - 反映確認は JS より**左サイドバーの「目次」**を見るほうが確実（JSは遅延する）
6. CTAのURLは1行単独で `type` → Enter で埋め込みカードになる
7. ハッシュタグは公開設定画面で入力 → Enter を1つずつ
8. 「投稿する」→ `/api/v3/notes/<key>` で
   `status:"published"` / `price` / h2数 / CTAリンク数 を確認

## noteエディタの操作（2026-08-27・2本目の公開で確定）

前回の手順に加えて、実際に踏んだ挙動。**ここが分かっていないと必ず壊す。**

### Enter は段落を分割しない（自動操作の場合）

ブラウザ自動操作で送る `Return` / `Enter` は、note エディタでは**改行（br）にしかならない**。
新しい段落は作られない。だから「行を type して Enter」を繰り返すと、
すべてが1段落に潰れる（前回「英数字が脱落した」と記録した現象の正体もこれ）。

→ **本文もCTAの文章も、段落は ClipboardEvent('paste') の `text/html` に
`<p>` を並べて一括投入する。** これは確実に段落が分かれる。

### 埋め込みカードの作り方（重要）

URL を type して Enter しても**カードにならない**。段落に URL の文字が残るだけ。

正しい手順は2段階:

1. カードにしたい位置の段落を triple_click で選び、`BackSpace` で**空の段落にする**
2. その空の段落に、`text/plain` に URL だけを入れた paste を投げる

これで `<figure>` の埋め込みカードになる（2本とも成功）。
選択範囲の上に paste すると**リンク（a要素）にはなるがカードにはならない**ので、
先に空にしてから投げること。

### 文末に新しい段落を作る

本文の下の余白（テキストが無いところ）を**実クリック**すると、
ProseMirror が末尾に空の段落を作ってそこにカーソルが入る。CTA はここから書き始める。

### 大見出しの付け方（座標は毎回測り直す）

paste では h2 が落ちる（P になる）ので、あとから1つずつ変換する。

1. 対象の段落を triple_click → `getSelection().toString()` が**その見出しと一致することを確認**
2. **別の呼び出しで**ツールバーの「見出し」ボタンの位置を DOM から取る
   （同じバッチ内で測るとツールバーがまだ描画されておらず取れない）
3. クリック → **また別の呼び出しで**「大見出し」ボタンの位置を取る → クリック
4. 反映は DOM 照会が遅れるので、**左サイドバーの目次**で確認する

**ツールバーの位置は開閉のたびに動く。** 古いスクリーンショットの座標を使うと外す。

### スクロールは実ホイールで行う（1ノッチ = 100px）

`window.scrollTo` / `scrollTop` 代入 / `scrollIntoView` は**効かない**（値が戻る）。
`computer` の scroll を使う。JS で測った座標は
**スクリーンショット座標 = ページ座標 × 0.8167**（ウィンドウ1920 → 画像1568）で変換する。

### 事故ったときの復旧

CTA を打ち込む前に、**必ず `getSelection()` のアンカーが末尾ブロックかを確認する。**
今回これを飛ばして、CTA が記事**冒頭**に入った（前回と同じ事故）。
Ctrl+Z で戻せるが、**20回押すと全文が消える。** その場合は Ctrl+Shift+Z で戻す
（13回で全文復帰、見出しは2つ失われたので付け直した）。

### 投入後の照合（推奨）

本文を投入したら、エディタ側の全ブロックのテキストを join したものと、
リポジトリの原稿から作った文字列とで**長さとハッシュを突き合わせる**。
今回は len 3133 / hash 353865558 が一致し、転記ミスが無いことを確認できた。


## noteエディタの操作（2026-08-28・3本目の公開で確定した改善）

前回までの「見出しはツールバーの座標を毎回測り直す」は**不要になった**。
エディタ左サイドバーの⌨アイコン（キーボードショートカット一覧）に記載がある。

### 見出しはキーボードショートカットで付ける

- **大見出し（h2）: Ctrl + Alt + 2**
- 小見出し（h3）: Ctrl + Alt + 3 / 本文に戻す: Ctrl + Alt + 0
- 下書き保存: Ctrl + S / 太字: Ctrl + B / 引用: Ctrl + Shift + >

手順（3本目で9個すべて成功）:

1. JS で対象ブロックを選択する
   `const el=pm.children[i]; pm.focus(); const r=document.createRange(); r.selectNodeContents(el);
    const s=getSelection(); s.removeAllRanges(); s.addRange(r);`
2. `computer` の key で **Ctrl+Alt+2** を送る
3. `pm.children[i].tagName === 'H2'` で確認する

**「JS でカーソルを置いてから type すると壊れる」は type の話で、
キーボードショートカットには当てはまらない**（3本目で実証。本文の len/hash が投入直後と
見出し設定後で完全に一致した）。

**ただし取りこぼす。** 9個中2個（index 18・44）が1回目で反映されなかった。
連続で送ると落ちるので、**適用後に必ず H2 の index 一覧を照合し、抜けを再実行すること。**
再実行時は選択と keypress の間に1秒待つと通った。

### 本文の一括投入と照合（2本目の手順のまま有効）

`ClipboardEvent('paste')` の `text/html` に `<p>` を並べて一括投入 → 80ブロックが正しく分割された。
投入後に「エディタの全ブロックを join した文字列」と「リポジトリ原稿から作った文字列」の
**len とハッシュを突き合わせる**。3本目は len 4038 / hash 1019815352 で一致。

### 埋め込みカードは「後ろのURLから」処理する

段落を空にしてから `text/plain` の URL を paste する手順は同じ。
**複数ある場合は index の大きいほうから**やる（前を先に変換すると後ろの index がずれうる）。
3本目は index 78 → 76 の順で2枚とも成功した。

### 公開後の検証（`/api/v3/notes/<key>`）

ハッシュタグは `data.hashtags` ではなく **`data.hashtag_notes`** に入っている。
`data.hashtags` を見ると空配列に見えるので誤判定しないこと。
