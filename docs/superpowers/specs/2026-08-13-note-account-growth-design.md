## 目的

記事生成システムは動いているのに、note アカウントが伸びていない原因を特定し、
「作る」だけでなく「届く」「読まれる」「売れる」までを通す。

### 1.7 診断

このアカウントの問題は**記事の質ではなく、出口と入口**にある。

- 出口: 投稿の自動化が停止している（作っても届かない）
- 入口: 検索流入する資産型記事を 1 年間作っていない（届いても読まれない）
- 転換: 40,077 PV から有料記事への導線がない（読まれても売れない）

記事生成システムの 6 役割は「生産量」を最適化する設計になっており、
**流通と発見性が誰の担当でもない**。

## 2. 方針決定（アカウント所有者の選択）

| 論点 | 決定 |
|---|---|
| 無料記事の役割 | **資産型に転換**。ニュース速報をやめ、検索需要のあるテーマに切り替える |
| 見出し画像の生成 | **HTML テンプレート → Playwright で PNG 出力** |
| 投稿の自動化範囲 | **公開まで全自動**（有料記事の価格設定を含む） |

※ この表は note 記法の制約（表を使わない）の対象外。設計書であり note 記事ではない。

全自動公開のリスク（内容ミスがそのまま公開される）は提示済みで、
所有者が了解のうえ選択した。リスク低減として鮮度ガード（3.3）を設計に含める。

## 3. 設計

3 フェーズ。**既存資産の回収 → 出口の復旧 → 入口の転換**の順に実行する。
Phase 0 は当日から効果が出るが、Phase 2 は効果が出るまで数週間かかるため
この順序とする。

各フェーズは独立して完結し、それぞれが 1 つの実装計画に対応する。
Phase 0 は手作業（note エディタ操作）が中心でコード変更を伴わない。
Phase 1 と Phase 2 はコード・設定の変更を伴う。

### Phase 0: 止血（既存資産の回収）

新規記事の作成より先に実行する。

### Phase 1: 出口の復旧

#### 1a. 見出し画像ジェネレータ

`note-blog` リポジトリ内で完結させる。

```
note-blog/
  images/
    template.html      # {{title}} {{category}} を差し込む HTML/CSS テンプレート
    render.mjs         # Playwright で 1280x670 の PNG を書き出す
    package.json       # playwright のみ
  articles/
    drafts/2026-08-13_foo.md
    images/2026-08-13_foo.png     # 記事と同じ basename
```

- 出力サイズ 1280x670（note 推奨）
- 入力: 記事ファイルの先頭 `# 見出し` をタイトル、`published.json` の `type` を
  カテゴリバッジ（有料 / 無料）に使う
- Chromium はローカルにキャッシュ済み（`~/AppData/Local/ms-playwright/chromium-1228`）
  のため追加ダウンロードは発生しない
- 生成した PNG は git 管理する。投稿前に目視確認でき、
  気に入らなければテンプレートを直して再生成できる

**なぜ HTML テンプレートか**: 日本語タイトルを画像内に正確に描画する必要があるため。
AI 画像生成は日本語文字が崩れ、毎回結果がぶれる。Canva は生成のたびに
API 往復が要り、無人の定期実行に組み込めない。HTML テンプレートは
コスト 0 円・結果が決定的・cron で無人実行できる。

**検証**: 既存記事 5 本のタイトル（長短さまざま）で生成し、
文字欠け・見切れがないこと、タイムライン縮小時も読めることを目視確認する。

#### 1b. note-post の拡張（nexeed-ops 側）

`nexeed-ops/tasks/note-post/index.ts`（334 行）に 3 点を追加する。

1. **見出し画像のアップロード**: 記事と同じ basename の PNG が
   `articles/images/` にあれば、エディタで見出し画像として設定する
2. **公開まで実行**: 下書き保存後に公開操作まで行う
3. **鮮度ガード**: 下記いずれかに当てはまる記事は公開せず「保留」とし、
   下書き保存だけ行って LINE に通知する

鮮度ガードの判定ルール（2 つ。どちらか 1 つでも該当すれば保留）:

- **ルール1（生成からの経過日数）**: 記事ファイル名の日付が実行日より 7 日以上前
- **ルール2（本文中の期限切れ）**: 本文に `YYYY年M月D日` または `M月D日` 形式の日付があり、
  その日付が実行日より過去で、かつ同一行に「期限」「締切」「終了」「まで」の
  いずれかの語が含まれる

ルール2 は月日のみの表記で年をまたぐ場合に誤判定しうる（例: 12 月の記事を 1 月に処理）。
誤判定した場合も「保留 = 下書き止まり + 通知」であり、記事が失われることはない。
保留は安全側に倒す設計とする。

鮮度ガードを入れる理由: バックログに「申請期限は 8 月 2 日」のように
既に無効な記事が含まれるため。全自動公開では、この判定がないと
期限切れ情報がそのまま公開される。

`selectors.ts` の各セレクタは既存分も含めて全て【未検証】のため、
初回は必ず `npm run task:note-post:show` で画面を見ながら 1 本通す。
画像アップロードと公開ボタンのセレクタは新規に特定が必要。

**検証**: `:show` で 1 本通し、note 上でタイトル・本文・見出し画像・公開状態を確認する。

#### 1c. 定期実行の再登録とバックログ処理

- `npm run arm:note` を実行してスケジュールタスクを登録し直す
- `NOTE_MAX_PER_RUN=1` を維持する（28 本を一気に公開すると
  タイムラインがスパム的になり、note 側の自動アクセス制限にも触れやすくなる）

バックログ 28 本は一括公開しない。3 分類して処理する:

- **そのまま公開可**: バージョン更新情報など、日付が過ぎても内容が有効なもの → 順次公開
- **鮮度切れ**: 期限・締切が過去のもの → 公開せず `articles/archived/` へ移動
- **後続記事に否定済み**: 例「Sonnet 5 の導入価格が 8 月 31 日で終了」は
  後続の「9 月値上げは中止」で否定されている → 統合するか破棄

分類結果は `articles/published.json` に記録し、判断の根拠を残す。

### Phase 2: 入口の転換

#### 2a. CLAUDE.md の改訂

無料記事の定義を「ニュースまとめ」から**資産型**に変更する。

- 検索需要のあるテーマを選ぶ（`◯◯ vs ◯◯`、`◯◯ 完全ガイド`、`◯◯ 使い方`）
- 1 年後も読まれる書き方にする（バージョン番号を主語にしない）
- 全記事の末尾に CTA を標準装備する

#### 2b. 新役割【集客】の追加

`prompts/08_growth.md` を新設する。

現行の 6 役割には「誰がこの記事を見つけるのか」を考える担当がいない。
これが 44 本が 50 PV 未満だった構造的な原因である。

責務:

- テーマの検索需要を確認してから【企画】に渡す
- タイトルに検索語を含める
- 既存記事との内部リンクを設計する

【企画】と【市場分析】の間に入る。

#### 2c. 有料記事は方針維持、導線のみ強化

CLAUDE.md の「稼ぐ特化」方針は変更しない。
有料記事が 8〜21 PV である原因は中身ではなく導線であり、
Phase 0 の施策と無料記事末尾からのリンクで解決する。

価格改定は販売データ（1.6 で未取得）を確認してから判断する。

## 4. やらないこと

- Canva / AI 画像生成の併用 — HTML テンプレートで足りる
- 既存記事の全面リライト — トップ 3 への末尾追記のみ
- 有料記事の価格改定 — 販売データを見てから判断する
- バックログ 28 本の一括公開 — 鮮度切れを含むため選別する

---

## 5. 成功条件

- Phase 0: 実施 1 週間後、有料記事の PV が実施前（8〜21 PV）を上回る
- Phase 1: 記事を push してから 30 分以内に、見出し画像付きで note に公開される
- Phase 2: 新方針で公開した記事が、公開 1 か月後に 100 PV 以上（現在の中央値 67 の 1.5 倍）
